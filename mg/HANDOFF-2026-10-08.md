## 1. The project in three sentences

This repository is a hard fork of OpenClaw (an open-source runner for autonomous OS-level AI
agents) that adds a deterministic **governance layer**: every agent tool call passes a
default-deny policy gate, every decision and administrative act goes into a keyed, hash-chained
audit ledger, four tiers of named human accounts (Root, Administrator, User, Viewer) operate it
through a dashboard, and an emergency kill switch stops an agent. It is Kinan's graduation project
(with Mohammad and Malek); the code is largely Claude's, and the report is Kinan's, written in his
Overleaf project. `mg/PROJECT-SUMMARY.md` has the long description.

## 5. Rules and traps (each one has cost a session before)

- **Kinan's standing instructions:** decide by precedent and record the decision rather than
  asking; fix errors on sight and sweep the class; prove a code defect with a failing test before
  fixing it; document everything in a dated `mg/WORK-LOG-*.md` as you go; explain decisions in plain
  terms (Mohammad joins with only the PDF report as background); editing upstream OpenClaw files is
  fine (the fork is the product).
- **Never run `git stash`** (it once swept all uncommitted work).
- **Shell heredocs and `node -e` collapse backslashes** (`\n`, `\\`) and backticks run as shell:
  write files with the Write/Edit tools, or use `String.fromCharCode(92)`.
- **Do not run `oxfmt` on `DOCUMENTATION-UPDATES.md`**: it rewrites `Section~1.3` to `Section~~1.3`.
  Format code files only. `chapter3.tex` is CRLF: never `sed -i` it.
- **oxlint `max-lines` is 700 code lines** for the UI and governance files; move a coherent unit
  out when a file reaches it.
- **Vitest runs in worker threads, so setting `HOME` does not move `os.homedir()`**: a test that
  touches the user's home (the trash) must inject its own path (`setTrashMoverForTests`).
- **Measure before explaining a latency** (finding 406); **a probe must drive the production caller**.
- Counts are re-derived before quoting (`docs-notes/WRITING-GUIDE.md` lists how). Never "all fixed".
- Report prose follows `docs-notes/WRITING-GUIDE.md` (section formula, current design only, no
  "silently", no capability-claim constructions).
