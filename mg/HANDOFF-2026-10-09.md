## 1. The project in three sentences

This repository is a hard fork of OpenClaw (an open-source runner for autonomous OS-level AI
agents) that adds a deterministic **governance layer**: every agent tool call passes a
default-deny policy gate, every decision and administrative act goes into a keyed, hash-chained
audit ledger, four tiers of named human accounts (Root, Administrator, User, Viewer) operate it
through a dashboard, and an emergency kill switch stops an agent. It is Kinan's graduation project
(with Mohammad and Malek); the code is largely Claude's, and the report is Kinan's, written in his
Overleaf project. `mg/PROJECT-SUMMARY.md` has the long description.

## 5. Rules and traps (each one has cost a session before)

- **Kinan's standing instructions:** decide by precedent and record the decision rather than asking;
  fix errors on sight and sweep the class; prove a code defect with a failing test before fixing it;
  document everything in a dated `mg/` log as you go; explain decisions in plain terms (Mohammad joins
  with only the PDF report as background); editing upstream OpenClaw files is fine (the fork is the
  product). Commit and push only on Kinan's word.
- **Never run `git stash`** (it once swept all uncommitted work). To compare against the committed
  code, copy the file aside, `git show HEAD:<file> > <file>`, run, copy back.
- **The pre-commit hook runs `oxfmt --write` on every staged file and re-stages it.** oxfmt turns a
  LaTeX `Section~1.3` into `Section~~1.3`; `DOCUMENTATION-UPDATES.md` is now in `.oxfmtrc.jsonc`
  `ignorePatterns`, but any other Markdown file with a bare `X~1` is still exposed: quote such
  references in backticks. After a docs commit, check `git show HEAD:<file> | grep -c "[A-Za-z]~~[0-9]"`.
- **Shell heredocs and `node -e` collapse backslashes** and backticks run as shell: write scripts and
  files with the Write/Edit tools. A multi-replacement script that exits on the first missing pattern
  writes nothing, so check its output before assuming an edit landed.
- **Tests on this laptop:** never run many vitest folders at once (ten together stalled for over an
  hour). The governance suite is
  `node node_modules/vitest/vitest.mjs run src/governance/ src/gateway/governance-*.test.ts ui/src/pages/governance/`.
  Upstream suites need their own config, `--config test/vitest/vitest.<area>.config.ts`, with a bare
  file-name filter (a repo-root path matches nothing, because the configs set `dir`). Known Windows
  failures that are this machine's, proved by restoring the committed files: SQLite `EBUSY` at clean-up,
  `/tmp` against `C:\tmp` expectations, a Unix executable-bit check, plugin-subagent tests that time out
  at 120 s.
- **The full lint gate** (`node scripts/run-lint.mjs`) takes 10–18 minutes; read its exit code, not its
  tail. The pre-commit hook's oxlint is not the full gate.
- **Vitest worker threads cannot redirect `os.homedir()` via `HOME`**: a test touching the trash must
  inject its mover (`setTrashMoverForTests`).
- **In the browser pane, click the reference you were just given**, never one typed from memory (three
  near-misses in the QA of 2026-10-09). Governance dialogs live in shadow DOM: find buttons by their text.
- **Test a redactor on the text it will meet**: run it over `docs-notes/`, `mg/` and `docs/`
  (`qa-scrub-lines.ts` in the 2026-10-09 scratchpad is the script) before trusting its own tests.
- Counts are re-derived before quoting (`docs-notes/WRITING-GUIDE.md` lists how). Never "all fixed".
- Report prose follows `docs-notes/WRITING-GUIDE.md` (section formula, current design only).
