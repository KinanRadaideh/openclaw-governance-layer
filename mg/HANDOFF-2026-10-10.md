## 1. The project in three sentences

This repository is a hard fork of OpenClaw (an open-source runner for autonomous OS-level AI
agents) that adds a deterministic **governance layer**: every agent tool call passes a
default-deny policy gate, every decision and administrative act goes into a keyed, hash-chained
audit ledger, four tiers of named human accounts (Root, Administrator, User, Viewer) operate it
through a dashboard, and an emergency kill switch stops an agent. It is Kinan's graduation project
(with Mohammad and Malek); the code is largely Claude's, and the report is Kinan's, written in his
Overleaf project. `mg/PROJECT-SUMMARY.md` has the long description (its header is dated
2026-09-20; the system description still holds, the dates in it do not).

## 5. Rules and traps (each one has cost a session before)

- **Kinan's standing instructions:** decide by precedent and record the decision rather than asking;
  fix errors on sight and sweep the class; prove a code defect with a failing test before fixing it;
  document everything in a dated `mg/` log as you go; explain decisions in plain terms (Mohammad joins
  with only the PDF report as background); editing upstream OpenClaw files is fine (the fork is the
  product). Commit and push only on Kinan's word.
- **Check free disk space first** (`Get-PSDrive C`). Never clone or install into WSL without
  several GB free: its virtual disk grows and never shrinks by itself (compacting needs an admin
  `diskpart`; WSL 2.4 disables sparse disks).
- **Never run `git stash`** (it once swept all uncommitted work). To compare against the committed
  code, copy the file aside, `git show HEAD:<file> > <file>`, run, copy back.
- **Scripted edits: never `String.prototype.replace` with literal text** (`` $` `` in a replacement
  copies the text before the match); use `split`/`join`, or the Edit tool.
- **Shell heredocs, `node -e` and backticks do not mix:** an inline script holding template literals
  or `\n` breaks or writes real line breaks (twice on 2026-10-10). Write the script with the Write
  tool and run the file; check after any scripted edit. A multi-replacement script that exits on the
  first missing pattern writes nothing, so read its output.
- **The pre-commit hook runs `oxfmt --write` on every staged file and re-stages it.** oxfmt turns a
  LaTeX `Section~1.3` into `Section~~1.3`; `DOCUMENTATION-UPDATES.md` is in `.oxfmtrc.jsonc`
  `ignorePatterns`, but any other Markdown file with a bare `X~1` is exposed: quote such references in
  backticks. Dry-run the formatter on copies before a docs commit; after it, check
  `git show HEAD:<file> | grep -c "[A-Za-z]~~[0-9]"`.
- **The 700-line limit is enforced** (oxlint `max-lines`, no suppression allowed by AGENTS.md):
  split a file that crosses it, as `user-store.ts` was split on 2026-10-10.
- **Tests on this laptop:** never run many vitest folders at once. The governance suite is
  `node node_modules/vitest/vitest.mjs run src/governance/ src/gateway/governance-*.test.ts ui/src/pages/governance/`.
  Upstream suites need their own config, `--config test/vitest/vitest.<area>.config.ts`, with a bare
  file-name filter; find a file's shard with `vitest list --config test/vitest/vitest.config.ts <file> --filesOnly`.
  A gateway test file run directly matches three projects; add `--project gateway-core`. Known
