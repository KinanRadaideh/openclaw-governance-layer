## 1. The project in three sentences

This repository is a hard fork of OpenClaw (an open-source runner for autonomous OS-level AI
agents) that adds a deterministic **governance layer**: every agent tool call passes a
default-deny policy gate, every decision and administrative act goes into a keyed, hash-chained
audit ledger, four tiers of named human accounts (Root, Administrator, User, Viewer) operate it
through a dashboard, and an emergency kill switch stops an agent. It is Kinan's graduation project
(with Mohammad and Malek); the code is largely Claude's, and the report is Kinan's, written in his
Overleaf project. `mg/PROJECT-SUMMARY.md` has the long description.

## 5. Rules and traps

All of `mg/HANDOFF-2026-10-10.md` §5 still applies; read it. The short form:

- **Kinan's standing instructions:** decide by precedent and record the decision; fix errors on
  sight and sweep the class; prove a defect with a failing test before fixing it; keep a dated log
  in `mg/` as you go; explain in plain terms (Mohammad reads too); upstream edits are fine. **Commit
  and push only on Kinan's word.**
- Never `git stash`. Scripted edits: split/join or the Edit tool, never `String.replace` with
  literal text. **Write any script containing backslashes or backticks with the Write tool**: on
  10-12 a `node -e` through bash mangled a `\n` inside a mutation and the script would not load.
- **New (D9): a test that writes `policy.json` by hand while the installation has a key now records
  an integrity alert** (one ledger entry, and the file is resealed). The fixture (`test-group.ts`)
  removes the policy file its seeding created and resets the seal state; a test that writes the file
  behind the store's back and counts ledger entries must expect the alert.
- **New (D9): the store never creates the ledger key.** A fresh test installation's first policy
  write is unsealed (no key yet); the ledger's first entry creates the key; the next write seals.
  Tests that need a sealed file write twice (see `storeWrite` in `policy-file-seal.test.ts`).
- **`policy-store.ts` and `audit-ledger.ts` are each about 688 counted lines** (limit 700): new
  policy-file logic goes in `policy-seal.ts`.
- **New (D7): a test that raises the gate's escalation must carry the marker** (`pluginId:
GOVERNANCE_APPROVAL_PLUGIN_ID`); another plugin's approval keeps OpenClaw's surfaces. Only the
  governance route may resolve a governance-owned approval (`asGovernanceAnswer`, finding 429): a
  test answering one through the approval runtime directly must go through that wrapper.
- **Never run `test/vitest/vitest.e2e.config.ts` directly** (its global setup rebuilds `dist`, and did
  part-way on 10-12): use a throwaway config without `globalSetup`, like
  `vitest.e2e-nosetup.config.ts` in this session's scratchpad.
- **No fixed future dates in tests**: D5's test broke itself on 10-12. Use `Date.now()` offsets.
- The full lint gate: `OPENCLAW_OXLINT_SHARD_CONCURRENCY=1 node scripts/run-lint.mjs --split-core`,
  about 40–50 minutes, alone. It does not run `oxfmt`: run `node_modules/.bin/oxfmt --check` on
  touched files yourself. Plain `oxlint` misses rules the gate enforces.
- **Run gates as one sequential background chain** (typecheck → suite → build → lint), nothing
  beside it (`gates.sh` in this session's scratchpad is a ready one).
- Tests: the governance suite is `node node_modules/vitest/vitest.mjs run src/governance/
src/gateway/governance-*.test.ts ui/src/pages/governance/` (~15 min); a gateway test file alone
  needs `--project gateway-core`. `governance-kill-background.test.ts` failed once under the full
  suite's load on 10-12 (stop confirmation) and passed alone and on the next full run: watch it.
- **A check must read a request exactly as the tool that acts on it does** (finding 428; D2).
- The browser pane crops the governance page; drive it from a page script (shadow DOM walk) and
  read text. The Control UI asks for the fixture's Gateway token (`qa/gateway-token.txt`) first.
