## 1. The project in three sentences

This repository is a hard fork of OpenClaw (an open-source runner for autonomous OS-level AI
agents) that adds a deterministic **governance layer**: every agent tool call passes a
default-deny policy gate, every decision and administrative act goes into a keyed, hash-chained
audit ledger, four tiers of named human accounts (Root, Administrator, User, Viewer) operate it
through a dashboard, and an emergency kill switch stops an agent. It is Kinan's graduation project
(with Mohammad and Malek; supervisor Dr. Haitham Al-Ani); the code is largely Claude's, and the
report is Kinan's, written in his Overleaf project. `mg/PROJECT-SUMMARY.md` has the long
description, and its §0 the state in one screen.

## 5. Rules and traps

All of `mg/HANDOFF-2026-10-10.md` §5 still applies; read it. The short form, with what 10-12 and
10-13 added:

- **Kinan's standing instructions:** decide by precedent and record the decision; fix errors on
  sight and sweep the class; prove a defect with a failing test before fixing it; keep a dated log
  in `mg/` as you go; explain in plain terms (Mohammad reads too, and his baseline is the 2026-08
  proposal, `Grad_Proj___Current.pdf`, so explain from the ground up); upstream edits are fine. **Commit and push only on Kinan's word**, code and documents
  as separate commits, never `.codex/`, push only to `personal`.
- **The report:** Chapters 1 and 2 are frozen; anything they get wrong is said in Chapter 3.
  Overleaf is the master; `DOCUMENTATION-UPDATES.md` is the one file of owed changes. In it, every
  report section number carries its title, `§` numbers are the file's own, and **change numbers
  (C1…) are stable: a done item is deleted and its number left unused; a new item takes the next
  free number and a row in §0.** Do **not** run `oxfmt` on it (`.oxfmtrc` ignores it: oxfmt turns
  `Section~1.3` into `Section~~1.3`). Edit LaTeX with backslashes through the Edit tool.
- **Counts:** re-derive before quoting. Test counts per file come from `vitest list` (static
  counting of `it(` misses generated tests: on 10-13 it gave 4 for a file with 73); a logging file
  needs its own config (`test/vitest/vitest.unit-fast.config.ts`, `vitest.logging.config.ts`).
- **Scripts:** write any script containing backslashes or backticks with the Write tool, never a
  shell heredoc or `node -e` (on 10-12 bash executed backticks inside a `node -e`). Scripted edits:
  split/join with a count check, or the Edit tool. A TypeScript check script needs
  `node --import tsx` and a `.mts` file run from the repository (relative imports). Never
  `git stash`.
- **`oxfmt --write` re-pads Markdown tables** in `GOVERNANCE.md`, `REMAINING-WORK.md` and the
  handoffs; the pre-commit hook does it anyway, so run it before committing and expect table-only
  diffs.
- **Tests:** never run `test/vitest/vitest.e2e.config.ts` directly (its global setup rebuilds
  `dist`); no fixed future dates in tests (`Date.now()` offsets); a test that writes `policy.json`
  by hand while a ledger key exists records an integrity alert (D9); a test raising the gate's
  escalation carries `pluginId: GOVERNANCE_APPROVAL_PLUGIN_ID`, and one answering it through the
  approval runtime goes through `asGovernanceAnswer` (D7, finding 429); the store never creates the
  ledger key (D9).
- **Gates:** the governance suite is `node node_modules/vitest/vitest.mjs run src/governance/
src/gateway/governance-*.test.ts ui/src/pages/governance/` (~16 min); the full lint gate is
  `OPENCLAW_OXLINT_SHARD_CONCURRENCY=1 node scripts/run-lint.mjs --split-core` (40–50 min, alone),
  plus `node_modules/.bin/oxfmt --check` on touched files. Run gates as one sequential chain with
  nothing beside them (the kill-switch test is load-sensitive). `policy-store.ts` and
  `audit-ledger.ts` are near the 700-line limit: new policy-file logic goes in `policy-seal.ts`.
- **Live checks:** a check must read a request exactly as the tool that acts on it does (finding
  428). The browser pane crops the governance page: drive it from a page script and read text. A
  mutation that does not load proves nothing (the scripts report INVALID).
