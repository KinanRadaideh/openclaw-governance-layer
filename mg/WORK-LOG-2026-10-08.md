### The investigation (code read 2026-10-08)

`subagent.run`, which `createGatewaySubagentRuntime` (`src/gateway/server-plugins.ts`) dispatches

### Decisions (by precedent, as Kinan asked)

- **D10. Who counts as "the system writing for itself" (B applies).** Heartbeat turns, the
  memory flush, plugin background runs (memory-core's diary and rewrite, workboard, any plugin
  calling `subagent.run` or `agent.runEmbeddedAgent`), the skill workshop reviews and the slug
  helper. Their prompts are assembled by the host from earlier conversations, files and events, so
  they are where file contents travel. **Kept in full** (a person or an operator wrote the words):
  chat and channel messages, command-line and HTTP prompts, the companion side question, the voice
  consult, and isolated scheduled jobs (whose message was written by whoever created the job). The
  plugin's identity comes only from `client.internal`, never from request parameters, the same rule
  `runtimePluginToolGrant` already follows.
- **D11. Fix 418 at each entry, not deep in the runner.** `runEmbeddedAgent` is not a single
  funnel: chat and scheduled jobs can run on a CLI backend that bypasses it, and chat retries one
  turn across fallback models. So the recorder is called once per turn where each surface starts
  the turn, and a guard test lists every caller of `runEmbeddedAgent` and `runCliAgent` outside
  tests as either covered or exempt, so a new upstream caller fails the test until someone decides.
- **D12. Exempt:** commitments extraction and the model probe (`disableTools: true`, they cannot
  act on the host); compaction summaries (a raw summarising run, the same reason
  `agentCommandInternal` already skips raw model runs).
- **D13'. The fingerprint is plain SHA-256 of the exact text the agent received**, so anyone holding
  a copy (OpenClaw keeps the session transcript) can show it is the same message; the text cannot
  be rebuilt from it. Not keyed: a keyed fingerprint could be checked only by key holders, and the
  standalone verifier already holds the key anyway.
- **D14. One turn, one entry.** A voice consult records the caller's words, then runs through a
  plugin's runtime whose wrapper would record the same run as a plugin background prompt. A
  duplicate guard keyed on agent and run id skips a second record within 10 seconds, marked only
  after a successful write; the window is short because a scheduled job reuses its session id as
  the run id on every run. The plugin wrapper records only where the run starts, not in the
  branch that delegates to the owning plugin's runtime.
- **D15. The plugin marker is gateway-only.** `backgroundPromptSource` sits on
  `AgentCommandGatewayIngressOpts` like `executionIdentityAdmission`, is omitted from the public
  `AgentCommandIngressOpts` type, and `agentCommandFromIngress` strips it at runtime, because a
  plugin claiming it would have its own instructions recorded as a fact instead of their text.
- **D16. Side questions.** Model narration keeps its text (it is what lets the trail read "it said
  X, then did Y") and now passes the second scrubbing pass. No ledger filter for background
  prompts: each is one labelled line; recorded as OPTIONAL in `DOCUMENTATION-UPDATES.md` §9.
- **D17. A plugin forwarding a person's words** (voice-call, through its own runtime) is recorded
  as a plugin fact, because the entry point is the only trustworthy signal; stated as a limit.
- **D18. Every free-form match becomes `***`**, never the upstream partial form (first six and last
  four characters): a free-form secret is often short, so the partial form would give most of it
  away.
