**What happened with the model (worth knowing next time):**

- Kinan has only a **Kimi Code subscription key** (`sk-kimi-…`). It works only with the
  provider `kimi` and the model `kimi/kimi-for-coding`. The `moonshot` provider needs a
  platform.moonshot.ai key (`sk-…` without `kimi`), and answers 401 to a subscription key.
- The onboarding live test first answered **403**, _"Your current subscription does not have
  access to Kimi Code right now"_. Later the same key probed **ok**, so it was most likely a
  usage limit and not the plan.
- Onboarding ended with **`Error: prepared model runtime publication timed out`**: upstream's
  model-runtime build has a 120 s limit (`src/agents/prepared-model-runtime.ts`), exceeded
  on the cold VPS. The key typed during onboarding was not saved. Finished by hand:
  `openclaw models auth paste-api-key --provider kimi` (one slip stored the command text as
  the key, shown by the masked preview `openclaw...moonshot`), then
  `openclaw models set kimi/kimi-for-coding`, then
  `openclaw models status --probe --probe-provider kimi`: **ok**. A leftover `moonshot`
  profile holds the same subscription key, unused.
- A probe takes about 110 s on the VPS.
